# Route Origin Headers v1 Contract

Producer:

- reference HTTP runtime responses from `orv run` / `orv run-build`
- generated native server route handlers when native lowering can preserve the
  same response origin
- production smoke tests generated by `orv build --prod`
- request trace frames through `response_origin_id`

Current regression coverage:

- `docs/samples/route-origin-server-route-v1.golden.json`
- `crates/orv-runtime/src/server/tests.rs::route_response_includes_origin_headers`
- `crates/orv-runtime/src/server/tests.rs::route_default_response_omits_response_origin_header`
- `crates/orv-runtime/src/server/tests.rs::route_response_origin_header_tracks_executed_branch`
- `crates/orv-cli/tests/origin_header_contract.rs::generated_smoke_freezes_origin_header_contract`
- `crates/orv-cli/src/build_deploy.rs` verify-build checks for route and
  response origin drift against `origin-map.json`

## Headers

Successful route matches emit:

```text
x-orv-origin-id: ori_...
```

When the response was produced by a known `@respond`, responses also emit:

```text
x-orv-response-origin-id: ori_...
```

Rules:

- Header names are lower-case in the public contract:
  `x-orv-origin-id` and `x-orv-response-origin-id`.
- Header values are origin ids from `origin-map.json`.
- `x-orv-origin-id` references the matched route origin.
- `x-orv-response-origin-id` references the executed `@respond` origin.
- If a route has multiple response sites, the response header follows the branch
  that actually executed.
- Default responses without an executed `@respond` omit
  `x-orv-response-origin-id`.

## Server Artifact Coupling

The published minimal server route fixture is
`docs/samples/route-origin-server-route-v1.golden.json`.

Server runtime artifacts expose route metadata:

```json
{
  "origin_id": "ori_route",
  "response_origin_ids": ["ori_response"]
}
```

Rules:

- `origin_id` must exist in `origin-map.json` and identify the route.
- Every `response_origin_ids[]` value must exist in `origin-map.json`, identify
  a `respond` domain origin, and be contained by the route origin.
- `response_origin_ids[]` values are unique per route.

## Smoke Test Coupling

Generated production smoke scripts must contain:

- `orv_smoke_origin_header`
- `orv_smoke_response_origin_header`
- exact `x-orv-origin-id` checks
- exact `x-orv-response-origin-id` checks for routes with one unambiguous
  response origin

Routes with multiple possible response origins are still verified through
runtime branch coverage and `verify-build` origin-map consistency. Generated
smoke checks exact response-origin headers only when one response origin is
unambiguous from server artifacts.

## Trace Coupling

Runtime trace frames carry the same response origin as:

```json
{
  "route_origin_id": "ori_route",
  "response_origin_id": "ori_response"
}
```

The trace contract is documented separately in
[Runtime Trace v1](RUNTIME_TRACE_V1.md).

## Version Policy

Route Origin Headers v1 is the public HTTP source-to-production header contract.
Breaking header-name, origin-id, omission, or branch-selection changes require a
contract update plus runtime, smoke, trace, and verify-build regression updates.
