## 코드 품질 소견

- **프로덕션 에러 처리 위생.** `orv-runtime/src/interp.rs`(12K줄)의
  비테스트 `unwrap/expect`는 3건뿐이고, `build_deploy.rs`의 `expect`는
  전부 사전 검증된 JSON invariant에 설명 메시지를 붙인 의도적 스타일이다.
  `parser.rs`의 `expect(` 다수는 파서 자체 메서드로 오탐. `TODO/FIXME` 0건.
- **경계 강제의 실행력.** platform boundary가 문서 선언이 아니라
  `dependency_boundary`/`commerce_boundary`/plugin boundary 테스트로
  실제 컴파일 그래프와 descriptor 레벨에서 강제된다.
- **계약 drift-guard 밀도.** golden JSON + extra-key/value-drift 거부
  테스트가 public artifact 전 표면을 덮는다.

### 문제인 것

- **거대 파일.** `orv-cli/src/tests.rs` 31K줄, `editor_lsp_dap.rs` 17.7K줄,
  `build_deploy.rs` 16.2K줄, `interp.rs` 12K줄. `orv-runtime/server`처럼
  facade + 하위 모듈로 이미 분리한 선례가 있는데 CLI 쪽은 방치됐다.
  clippy `too_many_lines` 경고도 이 파일들에 집중된다.
- **리뷰 불가능한 커밋 유닛.** `editor_lsp_dap.rs` 하나에 editor/LSP/DAP
  세 프로토콜이 공존한다. 다음 기능 추가 전에 분할이 선행돼야 한다.
- **죽은 테스트 support 코드.** `tests/dap_editor_source_bundle_contract/support.rs`에
  never-used 함수 9개(dead_code 경고). 공유 support로 승격하거나 삭제 필요.
- **경고 부채.** warn 레벨 pedantic/nursery 경고(`redundant_pub_crate`,
  `redundant_clone`, `needless_raw_string_hashes` 등)가 테스트 트리에
  수십 건 누적. 게이트는 아니지만 신호 대 잡음비를 깎는다.
- **CI 부재 증거.** clippy 회귀가 main에 들어왔다는 것 자체가 로컬 훅/CI
  게이트가 없다는 뜻이다. `G011-Z Work discipline`이 사람(에이전트) 규율에만
